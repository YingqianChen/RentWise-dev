## 结论

值得继续，但下一阶段应以可靠的小范围试用为目标。产品已经具备“导入资料 → 查看事实和来源 → 核实问题 → 整理沟通草稿 → 比较候选”的主要流程，仍未证明真实用户能顺利完成这些步骤，也未证明模型在真实资料中的可靠性。当前更接近功能较完整的开发原型，不宜宣布达到公开上线标准。

不使用一个笼统的“完成百分比”：页面齐全、模型表现、故障恢复和用户价值是不同维度，混成一个数字会掩盖真正的缺口。

## 产品为什么可能有价值

以下是产品判断和待验证假设，不是市场调查结论。

- 用户真正需要的是把分散、矛盾的广告和聊天记录变成可核对的事实，并知道下一句该问什么。
- 最有价值的区别是：多房源持续整理、用户修正不会丢、每项结论可追溯、调查进度能保存。仅仅“让 AI 总结房源”不足以构成长期优势。
- 自动排序应保持辅助地位。把未知误当风险、把未经核对的金额当事实，会直接削弱产品价值。
- 租房通常是阶段性需求，因此付费和留存方式尚需验证；暂不建设订阅、支付或复杂账号套餐。
- 当前没有真实用户行为或付费证据，商业价值尚未验证。下一步应观察 5 位目标租客使用匿名或自行脱敏的资料完成核心任务，而不是继续增加页面。

建议试用指标：首次导入能否独立完成；能否找到判断依据；是否识别费用未知/冲突；能否修正错误；能否在比较后生成有用的问题。记录失败原因、耗时和误判，不追求“所有人都喜欢”的口头反馈。邀请、对外沟通和收集真实资料需要项目所有者安排或明确授权。

## 功能取舍

| 决定 | 功能 | 理由与处理方式 |
| --- | --- | --- |
| 保留并完善 | 文字/截图导入、事实与来源、确认/修正、调查任务、沟通草稿、比较 | 直接服务签约前的信息整理和核实 |
| 保留 | 用户预算及租金、押金、杂费计算 | 比较用户自己的成本约束；不做市场估值 |
| 删除/停用 | 市场租金高低、区域中位数推导、低价判断 | 前序已从主要产品输出停用，本轮继续保持 |
| 删除 | 导入页按时间伪造的 OCR 进度 | 已移除；上传时只显示保存状态，分析进度由房源页读取实际状态 |
| 简化 | 金额结论里的内部字段名；外部字体下载依赖 | 已改为用户能理解的费用名称；采用系统字体，构建不再依赖 Google Fonts；生产构建明确采用已验证的 Webpack |
| 延后 | 通勤代理、法律检索、自动抓取链接、原生 App、多人协作、市场数据 | 不扩建。现有通勤代码和部分旧接口仍在，不能声称已全部删除 |
| 不开发 | 自动联系中介、支付、电子签约、保证识别诈骗、正式法律结论 | 超出当前产品范围 |
| 不扩大 | 同时深度比较的 5 个候选上限 | 暂未有用户证据表明需要更大表格；初筛需求应单独验证 |

## 本轮已落地的问题与解决方案

| 问题 | 影响 | 已完成的处理 | 验证 |
| --- | --- | --- | --- |
| 固定金额被当成租金倍数 | HKD 36,000 押金可能被乘以月租 | 区分具体金额、明确月数、香港按金写法；模糊数字保持未知 | 固定押金、两按一上、半佣、免佣、未知/范围测试 |
| 季度差饷按整笔加入月成本 | 错算超预算 | 从该费用自己的证据读取周期，季费除以 3、年费除以 12；周期未知不猜 | 数据库中验证每季 900 → 每月 900 的重新分析 |
| 新证据未及时保存或旧证据仍在内存 | 重算使用过期周期 | 计算前保存并重新读取完整证据 | 真实数据库回归 |
| 引文确实存在，但金额不在引文中 | 错误数字可能成为强判断依据 | 将无金额支持的明确声明降为推断；支持 18.5k 等金额写法 | 假金额、部分数字匹配、中文万元测试 |
| 用包水电的引文支持差饷已包 | 无依据减少费用未知项 | 引文没有明确点名费用时降为推断；补充差饷责任提示规则 | 本地证据校验通过；真实模型改善尚未验证 |
| 旧质量评分使用子串匹配 | furnished 能匹配 unfurnished；1800 能匹配 18000 | 改为完整规范化值/明确别名匹配，布尔值严格比较 | 相反含义和金额位数回归 |
| 质量样本缺少明确的未知答案 | 只测模型能否找到信息，少测是否会乱猜 | 新增 6 个差饷责任/未知/冲突场景，允许显式 null 期望 | 20 个样本的结构和隐私检查 |
| 服务失败混入“准确率” | 不能区分模型错与服务不可用 | 新增离线报告说明；连续两次不可用后停止后续请求，记录未运行样本 | 模拟请求数测试，无外部调用 |
| 上传缺少边界 | 大批图片或超长文本消耗内存及调用额度 | 最多 8 张；每张 10 MiB、总计 30 MiB；图片真实格式及 2500 万像素上限；文本合计 30,000 字符 | 限制、伪图片、半途失败清理测试 |
| OCR 文本可绕过输入限制 | 截图产生超长输入 | 发送模型前同时检查正文和 OCR 的合计长度；不偷偷截断 | 过长 OCR 场景断言不会调用模型 |
| 第二次选图覆盖第一次 | 用户以为已上传，实际丢了前批图片 | 累积选择、去重、删除单张、清晰的限制说明 | 浏览器和手机尺寸测试 |
| 图片读取失败后的“重试”只重新分析文字 | 图片型房源无法恢复 | 重试会再次读取失败图片，保留已成功读取的图片文本 | 真实数据库完整重试流程 |
| 更新文字时遗漏图片文字 | 来源组合前后不一致 | 编辑后仍保留图片 OCR 内容 | 代码核查，原有回归通过 |
| 回滚后读取已经失效的对象编号 | 错误处理可能再次报错 | 分析前保存编号，失败时按编号写回状态 | 数据库已有失败恢复回归 |
| 删除记录不删除上传文件 | 私人截图残留本地 | 删除候选/项目成功后清理对应上传文件；上传失败也清理已写入文件 | 文件测试与数据库删除验收 |
| 存储路径可跳出指定目录 | 错误键可能访问其他位置 | 校验解析后的路径必须留在存储根目录内 | 相对路径、绝对路径、符号链接测试 |
| 导入前不知道资料发往哪里 | 用户无法判断应提供哪些资料 | 新增脱敏提醒及 AI/OCR 处理说明 | 浏览器验收 |

费用规则的限制：当前只对差饷增加有证据的周期判断；管理费周期、一次性费用分类、押金退还与预付时间线仍需结构化建模。本轮没有假装把这些都完成。已确认的旧差饷数值没有冻结周期，不能借用后来分析的周期；用户可按页面说明修正为每月等值。原始数值和原文仍保留。

## 真实模型试跑：没有通过

第一次在网络隔离中连接失败。获得网络权限后，按授权发出 20 次请求，SDK 自动重试关闭；3 个样本完成，17 个返回 `llm_unavailable`。没有继续请求，没有发送真实租客资料，没有把密钥复制到仓库。

本次完整运行失败。不能把 0.149 解读成模型准确率，也不能声称差饷已从约 72.7% 提升。已完成的三个样本还有完整租期/车站写法与旧别名不一致的问题，需要人工检查。旧 0.947 与新的严格评分口径也不可直接比较。

后续本地证据校验补丁没有再调用真实模型验证。报告会保留这个缺口；不会通过降低门槛或恢复宽松子串匹配掩盖失败。

## 本轮环境与交付边界

- 代码位于当前工作区的 `RentWise/` 独立副本，原桌面项目未修改。
- 复用原 Python 3.11 环境；前端依赖是本地副本，不重新安装软件或改系统设置。
- 新建隔离测试库 `rentwise_review_test`，只运行和清理测试账户；没有更改开发库或执行旧数据搬运。
- 独立副本的 `.env` 只有本地测试配置，无第三方密钥；真实评测临时读取原项目 Key 到进程内，没有输出 Key。
- 本轮没有合并主分支、推送 GitHub、部署网站、发送消息或清理原目录里的数据。
- 修复影响新分析/重算；没有批量重新处理原开发数据库的房源。
