# 第二批：分析可靠性与调用控制

本批由用户授权继续修改并直接 push，先审查和测试。没有新增付费模型请求、部署或数据库迁移。

## 产品取舍

保留“整理来源、明确费用、核实缺项、比较候选”的产品定位。先让一次分析可靠地完成或失败，并让用户知道如何继续。删除自动起名时的额外 AI 请求，直接用已提取的地区和租金命名。

## Review 发现与修复

| 问题 | 实现 | 验证 |
| --- | --- | --- |
| 连续点击重试可能并发分析并覆盖结果 | PostgreSQL 事务级 advisory lock；同一候选互斥，不同候选可并行；冲突返回可读的 409 | 同时发起真实 HTTP 请求，模型模拟器仅执行一次 |
| 分析期间编辑来源、修改确认值、删除候选或项目、修改项目预算可能与旧计算冲突 | 候选写操作共享项目锁；项目修改/删除获取项目独占锁；取得锁后再读快照，提交后才释放 | 分析阻塞时，上述操作均返回 409；原分析结束后重试成功 |
| 进程中断后一直显示“处理中” | 新增“Check interrupted analysis”；必须取得候选锁且状态超过一分钟才标记为中断；保留来源，再由用户点击重试 | 遗留队列记录可恢复；活动任务不能被误恢复；检查本身不调用模型 |
| 延迟到达的后台任务重复运行 | 后台入口仅领取仍为 queued 的候选 | 恢复后的旧后台回调不再开始分析 |
| 模型/分析长时间不返回 | 默认单个模型请求 60 秒、完整分析 180 秒；超时转为可重试失败 | 同步分析及后台分析超时均保存安全错误和来源；重试成功 |
| SDK 隐含重试增加请求数 | Groq `max_retries=0` | 内存 HTTP transport 模拟 503，确认仅发送一次请求 |
| 自动命名多耗费一次 AI 请求 | 使用现有资料本地生成名称，删除不用的命名 prompt | 无名称导入仅一次提取请求，名称正常显示 |
| 修改预算时差饷证据未加载 | 项目重算一次加载字段和 evidence | 差饷月费保留，预算结论更新，全程无模型调用 |
| 回滚后的对象 ID 可能触发隐式数据库读取 | 第一批追加修复：使用请求 ID 和 ORM 已认证身份重新加载 | 来源编辑遇到服务超时仍返回保存的来源和安全失败状态 |

锁使用独立、不复用的连接，避免锁占满处理业务所需的连接池。锁覆盖管线内部的多次提交，依靠数据库事务结束释放。新增接口复用身份认证及项目归属检查。无新依赖、无表结构变化。

## 验证及范围

- 后端普通回归、PostgreSQL 集成、Ruff、前端 lint / TypeScript / 正式构建和浏览器检查均须通过后推送；最终数量见 `2026-09-09-validation.md`。
- 集成测试使用独立 `rentwise_review_test`，模拟模型和合成账户。没有使用开发数据库，也没有真实租客资料。
- 并发检查覆盖 HTTP 请求；取消检查覆盖数据库事务锁；遗留记录覆盖服务中断后的恢复入口。**没有把这些等同于完整的进程强杀或生产负载测试。**
- 任务仍为进程内后台执行，尚非持久队列；进程退出后需要手动检查和重试。队列启动时若项目正被修改，后台领取可能被拒绝，恢复入口可解开遗留状态。
- PostgreSQL 的事务连接需能覆盖整个分析时长；部署时应核对代理/数据库的空闲事务超时和连接容量。若数据库连接被外部强制终止，完整的任务代次隔离和自动重投仍需在持久队列阶段完成。
- 客户端取消或超时不保证第三方立即停止计费；本批控制本应用的重复发起，不宣称提供精确账单上限。
- 真实模型准确率的缺口仍在：上一批批准的 20 次请求已用完，本批未追加。公开试用前仍需成功完成独立模型评测和真人试用。
