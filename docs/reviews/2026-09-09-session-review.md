# 第五批：会话退出与异常恢复

上一批 `a2be6f9` 已推送至用户确认的 `YingqianChen/RentWise-dev` 的 `codex/product-quality-review` 分支，前后端 [CI 均通过](https://github.com/YingqianChen/RentWise-dev/actions/runs/34322984733)。本批继续修复会话生命周期，没有真实模型请求、部署或真实数据库变更。

## 问题与实现

| 问题 | 处理 | 验证 |
| --- | --- | --- |
| Sign out 只清浏览器存储，原令牌仍可访问 API | 新增幂等 POST `/api/v1/auth/logout`；提交撤销记录后才返回 204；所有认证请求查询撤销状态 | 并发退出写入一条记录，原令牌访问账户和项目均返回 401；新的独立登录仍可用 |
| 同一用户同一秒登录可能签出完全相同的令牌 | 每次签发新增随机 `jti`，逐会话撤销 | 连续签发的撤销标识不同 |
| 按原始 JWT 字符串计算撤销摘要会被等价编码绕过 | 只对验签后确定的身份声明生成撤销键，使用用户 ID 与 jti；旧令牌兼容用户 ID 与 exp | 原始及增加签名填充的变体均被撤销；旧令牌也可安全退出 |
| 过期校验取整可能让刚清理的撤销记录短暂失去保护 | 明确在 exp 到达时拒绝令牌，拒绝不能安全持久化的到期值 | 到期瞬间、超大值、字符串、布尔值测试通过 |
| 项目列表将任意请求失败当作退出，甚至跳转循环 | API 统一只在携带当前令牌的请求返回 401 时清除会话；其他错误保留会话、显示错误和重试 | 403/429/503 不退出、不显示假的空列表；重试恢复 |
| 旧请求迟到的 401 可能误清新登录 | 清理前核对该请求的令牌仍等于当前浏览器令牌 | 延迟 401 到达时新令牌保留 |
| 退出后另一个标签页继续显示私人页面 | 受保护页面统一监听会话变化、跨标签页 storage 事件及页面恢复；退出或换账号后丢弃页面状态重新导航 | 两个已打开标签页同步回到登录页；嵌套页面的失效会话不会跳转循环 |
| 退出失败仍表现成成功 | 等服务端确认后再清浏览器；响应失败显示未确认并允许重试 | 首次 503 保留凭据，第二次成功退出；重复撤销幂等 |
| 私人 API 响应可被客户端缓存 | 认证及携带 Authorization 的响应附加 Cache-Control: no-store；客户端 fetch 使用 no-store | 令牌签发及认证失败响应头回归通过 |

撤销标识的设计参考 [OWASP JWT Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_Cheat_Sheet.html)：JWT 撤销应依赖可信身份声明，不能仅对可变的令牌字节表示做摘要。实现只接受现有 HS256 签名，没有引入新的签名算法或依赖。

## 运行与剩余边界

新增迁移 `20260909_0020`。部署次序：备份数据库 → 应用迁移 → 启动支持撤销的后端 → 发布新前端。当前仅独立 `rentwise_review_test` 应用过该迁移。不能简单回滚到不检查撤销的旧鉴权代码，否则未过期的已撤销令牌可能重新有效；回滚需保持撤销检查，或由操作者决定作废全部旧会话。

退出只撤销该令牌，不能取消已经通过认证并正在执行的请求。旧版没有 jti 的同用户、同到期秒令牌原本就不可区分，作为同一旧会话处理。过期撤销记录在后续退出请求时清理，不承诺到期即刻物理删除；账号删除的数据库级联会一并移除关联记录。

浏览器仍使用 localStorage 保存 bearer token；本批没有把它包装成完整会话架构升级。HttpOnly cookie、账号删除、密码找回及全部设备退出仍需后续设计。退出响应丢失时服务端状态可能已经改变，因此只提示“未确认”，不声称服务器一定仍保持登录。无完整渗透测试或真实模型质量验收，不能由本批测试推出“零漏洞”。
